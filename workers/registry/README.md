# KOV 등록 명단 동기화

공개 명단의 유일한 기준은 소유자가 읽기를 허용한 운영진 관리 기록이다.
- 팀관리: 898738915085799464
- 클랜관리: 898738968638672906
- 프리미어: 1337304240229580851
일반 신청 채널과 O/X 반응은 현재 명단의 직접 입력으로 사용하지 않는다. 기존 events.mjs/core.mjs 이력 파서는 과거 데이터와 테스트용으로 보존한다. 봇은 Discord 메시지나 역할을 쓰지 않는다.

## 실행과 저장
Node 24, npm ci, npm run registry:worker. 환경변수는 KOV_REGISTRY_BOT_TOKEN, UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN, BLOB_READ_WRITE_TOKEN이다. 비밀값은 환경으로만 주입한다. Docker 빌드도 잠금 파일로 설치한다.

Gateway 이벤트는 변경된 관리 스레드만 무효화한다. 기본 2초 동안 묶어 처리하며, 신규/수정/삭제/제목 변경/해체를 현재 기록으로 다시 계산한다. 전체 활성·보관 스레드 대조는 시작/새 Gateway 세션과 하루 1회 수행한다. 재시작 후 전체 대조로 세션 체크포인트와 메모리 작업 사이의 공백을 복구한다. Redis 캐시는 스레드별 해시 필드로 저장하고 변경 필드만 갱신한다. 공개 최종 명단은 내용이 달라졌을 때만 교체한다. 불완전한 수집 결과는 공개하지 않는다.

단일 실행 lease는 180초, heartbeat는60초다. 저장소 제한 시5분간 냉각하며 컨테이너 재시작 폭주를 피한다. /health는 프로세스 liveness이며 Discord 연결의 증거가 아니다. 실제 연결은 공개 API liveConnected와 liveUpdatedAt으로 판정한다.

## 조회와 백업
사이트와 API는1분 공용 캐시 및 동시 요청 합치기를 사용한다. 웹 요청은 Discord 전체 스캔을 시작하지 않는다. 팀 상세는 열 때만 조회하며 Discord 태그는 Redis24시간, 상세 응답은 CDN1시간 캐시한다. 명단의 source URL이 바뀌면 상세 캐시 키도 바뀐다.

공개용으로 정리된 이름·명단만 Vercel Blob public-v1.json에 백업한다. 토큰·메시지 원문·관리자 내부 메모는 백업하지 않는다. 백업 쓰기는 내용 변경 시에만, 최대 시간당1회다. Redis 장애 시 API는 프로세스의 마지막 정상 명단 또는 Blob 백업을 사용하며 stale=true, liveConnected=false와 기준 시각을 표시한다. 브라우저에도 마지막 정상 명단을 보관한다. 만료된 임시 명단은 백업에서도 제외한다.

Redis가 모든 명령을 거절하고 아직 백업이 없는 경우에도 봇은 승인된 관리 채널을 읽기 전용으로 전체 수집해 백업을 만들 수 있다. 이 장애 경로는 최대 시간당1회이며 실시간 연결로 표시하지 않는다. 저장소 복구 후 정상 실시간 처리를 재개한다. Blob도 한도에 걸리면 마지막 브라우저 캐시만 남을 수 있다.

## 무료 사용량
Redis 명령 및 JSON 입출력 바이트는 앱 단위로 모아5분마다 계측한다. 계측 시작 전 사용량, 실패 명령, HTTP 오버헤드 등은 포함되지 않으므로 실제 공급자 청구량의 완전한 대체가 아니다. 월별 계측치를 합산해70%에서 이벤트 묶음60초,90%에서5분으로 조절하고 KOV_REGISTRY_BUDGET 로그를 출력한다. 사이트 갱신도90%에서5분으로 늦춘다. Codex의 기존 kov 자동 점검은 시간마다 실제 공급자 사용량/제한 및 계측70/90 단계를 비교해 새 변화만 알린다. 공급자 콘솔 접근이 없으면 정확한 사용량을 확인할 수 없다.

Vercel Daemon 최소1Gi 설정을 유지한다. 무료 메모리420GB-hour로는1Gi 한 인스턴스를 한 달24시간 내내 운영할 수 없다. 코드 최적화만으로 이 제한이 없어지지 않으며 유료 전환은 하지 않는다. 별도 상시 무료 실행 환경이 연결되지 않은 상태다.
